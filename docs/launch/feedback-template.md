# Trial feedback and case-study template

Record only observed outcomes. Leave unknown fields blank. Keep a private working
copy until the participant approves any public attribution or shared material.

## Trial record

- Date and judg3d version:
- OS and Node version:
- Participant's workflow, without private client details:
- Installation completed? If not, where did it stop?
- Asset format and general purpose; no private path required:
- Profile used and why its limits fit the task:
- Result and executed coverage:
- Was the result independently verified? How?
- Action taken because of the report, if any:
- Most confusing message or interaction:
- Approximate trial time:
- Would the participant use it again? Why or why not?
- Related public issue or reviewed fix, if one exists:

## Before publishing a case study

- Confirm permission to publish the participant's name or use an anonymous role.
- Confirm permission for each quote, screenshot, asset and report.
- Describe the original task, observed result and resulting action.
- State limitations and unsuccessful steps.
- Count unique assets separately from repeated runs.
- Identify maintainer assistance; do not present a guided demo as independent use.
- Link the tested release and reproduction where publication is permitted.

No outcome, testimonial or adoption count is implied by the presence of this template.
